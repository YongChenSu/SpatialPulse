# 2025 產權建物數位孿生候選：長虹雲端科技大樓

| 項目 | 內容 |
| --- | --- |
| 日期 | 2026-11-03 |
| 狀態 | Phase 1 implemented / cadastral geometry pending |
| Branch | `feat/smart-campus-gis` |
| 資料來源 | 臺北市 `CB_2025_20250825` I3S、本機 snapshot、公開建築資料 |

## 目標

將「全市背景建物」與「2025 產權建物」拆成兩個獨立頁面，並從產權資料中選出一棟資料量充足、適合展示 Building Automation 與 Facility Management 的建築物，作為下一階段數位孿生監控主體。

## 頁面責任重新劃分

### 城市概覽頁

建議路由：`/gis`

- 只使用 NLSC `114_A` 2025 分棟建物。
- 呈現臺北市城市量體與區域空間關係。
- 提供行政區、區域或建物搜尋入口。
- 不載入 CB_2025 產權樓層幾何。
- 不處理單棟設備與即時監控。

### 產權建物與數位孿生頁

建議路由：`/gis/cadastral`，後續可延伸為 `/gis/cadastral/:buildingId`。

- 只載入 `CB_2025_20250825`。
- 提供門牌、樓層、用途、建材與使用執照查詢。
- 以選定建築為焦點，不與城市背景模型疊加。
- 顯示樓層、設備分類、能源、告警與維護面板。
- 官方產權欄位與模擬 IoT 監控資料必須清楚標示來源。

## 本機資料盤點方式

盤點資料：

```text
data/processed/taipei-cadastral-2025/nodes/
```

分析方式：

1. 只讀取沒有 children 的 leaf nodes，降低跨 LOD 重複計算。
2. 解碼 I3S attribute binary。
3. 以 `建物門牌` 聚合 feature。
4. 比較 feature 數量、樓層種類、層數、用途、建材、使用執照與完成日期。
5. 再以相同使用執照聚合多個門牌，還原同一棟大型建築。

本次共找到約 1,353 組門牌。feature 數最高的候選多為大型集合住宅，雖然產權筆數多，但與智慧商辦、設施維運及公司職缺情境的關聯較弱。

## 為什麼適合當主力數位孿生案例

### 與產品目標一致

- 大型科技商辦比集合住宅更貼近 Building Automation。
- 30 層加 4 層地下空間，適合展示樓層 drill-down。
- 辦公、商店、停車等混合用途，適合建立分區能耗與設備策略。
- 建築高度與規模足以呈現 3D、GIS 與 FM 整合價值。
- 位於內湖科技走廊，符合智慧建築作品的敘事。

### 可規劃的監控模組

第一階段可建立情境資料，不宣稱是真實現場 IoT：

| 系統 | 可展示內容 |
| --- | --- |
| 電力 | 全棟需量、樓層用電、尖峰負載、契約容量 |
| 空調 | 冰水主機、AHU、VAV、供回水溫度、COP |
| 室內環境 | 溫度、濕度、CO₂、PM2.5 |
| 電梯 | 運行狀態、等待時間、故障與維護 |
| 門禁 | 訪客、異常開門、夜間進出 |
| 消防 | 偵煙、灑水、消防泵、排煙設備 |
| 停車 | 455 個平面車位的使用率與尖峰流量 |
| 告警工單 | 告警確認、派工、處理、復核與 SLA |

### 資料來源分層

```text
官方真實資料
├── CB_2025 幾何與產權欄位
├── 門牌、樓層、使用執照與完成日期
└── 公開建築基本資料

SpatialPulse Scenario Data
├── 即時能源與空調 telemetry
├── 感測器及設備狀態
├── 告警與維護工單
└── 歷史趨勢與 KPI
```

UI 必須持續顯示 `Official Building Data` 與 `Simulated Operations`，避免把作品集情境資料描述成建築現場真實數據。

## 建議資訊架構

```text
/gis
└── 臺北市全市背景建物
    └── 前往產權建物分析

/gis/cadastral
└── 2025 產權建物搜尋與選取
    └── 長虹雲端科技大樓
        ├── 建築總覽
        ├── 樓層與產權空間
        ├── 能源監控
        ├── 空調與環境
        ├── 設備及告警
        └── 維護工單
```

## 實作順序

1. 將 NLSC city context 與 CB_2025 拆成不同 route，不再提供同頁雙 layer checkbox。
2. 建立長虹雲端建築 profile，使用 `110使字84` 聚合 533–539 號資料。
3. 進入產權頁時將相機定位到 121.6157, 25.0719。
4. 只顯示或強調該使用執照對應的 features。
5. 建立樓層索引與右側官方資料卡。
6. 加入明確標示的 simulated monitoring schema。
7. 串接既有 WebSocket telemetry，但使用獨立 building ID，不沿用 A1 數據中心名稱。
8. 建立官方資料、scenario data 與 UI mapping 的測試。

## 仍需驗證

- CB_2025 feature 是否能直接依 `使用執照字號` 套用 Cesium style filter。
- 同一使用執照跨 node 的 feature picking 與 highlight 行為。
- 地下層及共有部分是否預設隱藏。
- 產權幾何與正射影像的水平對位稽核。
- CB_2025 高度欄位的 binary null encoding，目前不能直接使用初版 decoder 的數值結果。

## 決策

目前推薦以長虹雲端科技大樓作為第一個真實建物基底的 Digital Twin 案例。它不一定是 CB_2025 feature 數最多的門牌，但在資料量、建物規模、用途與作品敘事之間最平衡。
